## Git 工具是什么？

Git 是一个开源的**分布式版本管理系统**，这个定义可能会略微抽象，具体来说，当你在编辑改动你的项目文件夹时，你可能会希望保留一份未改动的版本，避免整个项目在本次编辑改动后出现问题，难以回调。最简单的做法当然是直接复制一份项目文件夹来编辑修改，但是当迭代版本次数多了，容易出现混淆，并且如果项目文件很大，会非常占用空间。除此之外，如果是多人协作开发一个项目文件的情况，管理和同步多方的改动会是一件很麻烦的事。Git 工具正是为了解决这些问题而诞生的。



Git 的思想是在各自设备中管理一个该项目的**本地数据库**，当你完成一次对项目文件的修改后，你可以提交到本地数据库中，并且标注本次修改内容。将来你可以随时回看你过去的每一次提交，可以随时将项目回滚到任何一次提交时的状态。对于多人协作开发的情况，则是多方本地数据库连接同一个**远程数据库**，每个人可以选择将远程数据库更新的项目文件同步到本地数据库，也可以将本地数据库的修改上传到远程数据库。



## Git 基础知识

Git 具体是如何工作的？一开始你已经在你的设备上有了一个项目文件夹，当你将你的项目初始化为 Git 项目仓库后（后续会讲如何获取 Git 仓库），你的项目文件夹中会出现一个`.git`隐藏文件夹。此时你的项目文件夹就是你的**工作区**，当你让 Git 完成对你各个项目文件的**跟踪**后，你就可以开始对你的项目文件进行任意的编辑修改。



当你完成各种各样的编辑改动后，想记录当前项目作为一个新版本，你就可以先将改动文件放到**暂存区**，到这一步 Git 还不会将当前项目状态作为一个新版本保存，因此暂存区起到一个“缓存”的作用，可以让你确认你做了哪些修改，再次考虑是否要将这些修改保存为一个新版本中，另外，在发生“合并冲突”的情况时，暂存区会起到“标记冲突是否解决”的作用，不过这是使用远程仓库的情况，后面再详细说明。



在你确定暂存区对于当前项目的“快照”就是要提交的一次版本后，你就可以将暂存区的内容提交到**本地仓库**中，并且在本次提交中，你可以写上提交说明，方便以后查询本次提交的更新内容。Git 的工作流程示意图如下所示。

**远程仓库**是指托管在因特网或其他网络中的你的项目的 Git 仓库，这样就可以通过在本地仓库中添加远程仓库链接来实现多人协作。你可以随时拉取远程仓库的最新版本到本地仓库中进行更新，当你拥有远程仓库的读写权限时，你也可以选择将本地仓库的版本推送到远程仓库的版本链中，但是这个过程中可能会出现“合并冲突”的情况。



举个例子，用户一和用户二共同管理远程仓库，此时二人的本地仓库都存储远程仓库的最新版本 A，此时用户一在完成一次更新后往远程仓库推送版本 B，而用户二在本地仓库更新了版本 C，但是用户二的本地仓库对远程仓库的记录仍停留在版本 A，此时 **Git 会要求用户二将本地仓库对远程仓库的记录更新到最新版本后才能推送**。当用户二拉取（pull）远程仓库最新版本 B 时，Git 会尝试将版本 B 和本地仓库的版本 C 进行合并（merge），若有难以兼容的合并（例如版本 B 已经删除文件 a，而版本 C 则对文件 a 进行了修改），则 Git 会提示发生“合并冲突”，并要求用户二手动介入，修改冲突后才能完成合并。之后用户二就可以将本地仓库合并好的版本 C` 推送到远程仓库作为最新版本。



以上是目前整理的基础知识，其他更多知识或细节可能以后会补充，或者包含在下一节的常用命令中。



## 常用命令

### Git 仓库配置

Git 提供了一些配置变量来供用户选择，包括用户身份、默认文本编辑器、仓库默认分支名、命令别名、界面显示等。通常使用`git config`来进行编辑。总共有三个配置文件，并且分别有不同的作用域：

~~~powershell
# 系统级：存放在 Git 安装目录下的 /etc/gitconfig ，作用于当前计算机上的所有用户。
git config --system
# 用户级：存放在用户目录下的 ~/.gitconfig ，作用于当前用户的所有仓库。
git config --global
# 仓库级：存放在项目文件夹的 .git/config ，作用于当前仓库。
git config --local
~~~

### Git 仓库获取

Git 仓库通常有两种获取方式，一是直接在本地项目文件夹中初始化，二是从其他服务器上克隆一个 Git 仓库到本地。

~~~powershell
# 在本地项目初始化，并且要让项目中的文件被 Git 跟踪。
git init 
git add . # 将当前文件夹下的所有文件提交到暂存区
git commit -m "initial project version" # 将暂存区内容提交到本地仓库，从而实现Git对所有文件的跟踪

# 克隆已有仓库，可以使用https://协议、git://协议和SSH传输协议，并且可以自定义仓库名字
git clone # git clone <url> <newname>
~~~
